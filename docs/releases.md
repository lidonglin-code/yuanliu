# 源流版本维护说明

## 获取代码

仓库主页的 **Code → Download ZIP** 提供当前默认分支的代码。**Releases** 提供维护者发布的版本与更新说明。

下载源码后，按根目录 README 启动本机服务。GitHub 仓库地址是代码分发入口，不是已经运行的在线工作台；智能模式需要本机网关。

## 日常迭代

1. 修改代码并在本机验证。
2. 运行前端及网关测试。
3. 检查待提交文件，不包含个人备份、日志或 API Key。
4. 提交代码，写清此次改动的内容。
5. 推送到 GitHub。较大的修改可使用独立分支和 Pull Request 审阅后合并。

提交是代码历史的一次记录；推送把提交同步到远程仓库。无需每次提交都发布发行版。

## 发布版本

首次可用预览版使用 `v0.1.0`；新增功能可发布 `v0.2.0`，修复问题可发布 `v0.1.1`。这些是本项目建议的版本规则。

在 GitHub 的 **Releases → Draft a new release** 中选择要发布的提交，创建对应标签并写更新说明。预览版本勾选 **pre-release**。确认后发布，用户就可以从该版本下载源代码。

不要将个人浏览器数据、工作备份或运行日志添加为 Release 附件。

## 用户更新与数据

1. 在现有工作台导出备份。
2. 停止当前本机服务。
3. 下载并解压新版本，按 README 启动。
4. 使用相同浏览器和 `http://127.0.0.1:4567/` 打开，核对现有数据；需要时恢复备份。

工作记录存储在浏览器中，不会随代码推送到 GitHub，也不会自动被其他人看到。GitHub 下载不会自动替用户安装新版本。
